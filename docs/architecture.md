# Архитектура, перенос и границы

Один ведущий агент среды читает AGENTS.md и выбирает действие. Python CLI детерминирован:
extract/fetch → источник и хеш → claim с цитатой/зависимостями → записи стратегий,
решений и обещаний → checkpoint → resume → revise/impact. Никакой внешний модельный
API из Python не вызывается. Демо — реально выполненные инструменты и синтез текущего
агента; replay CLI не генерирует новое исследование.

| Слой | Файлы | Доверие |
|---|---|---|
| Постоянные инструкции | AGENTS, instructions, workflows, prompts | инструкции проекта |
| Методика | knowledge | справочник метода, не факт о продукте |
| Материалы и происхождение | projects/*/inputs, sources, evidence/SRC-*.json | недоверенные данные |
| Состояние и память | state/project.json, history, checkpoint | проверяемые записи; прошлый ответ не источник |
| Результат | outputs, decisions, logs | предложенные выводы со статусом и границами |

Единая JSON-база проекта содержит sources/claims/decisions/promises/strategy/workflow/
budget/events. SHA256 envelope обнаруживает случайное повреждение (не цифровая подпись
против злоумышленника). Транзакция защищена эксклюзивным lock и optional expected_revision,
пишется через fsync + os.replace. Старый снимок сохраняется до commit. Извлечённые
артефакты пишутся до базы: после аварии могут остаться неиспользуемые файлы, но ссылка
на незавершённую запись не считается commit. Проверка не гарантирует сохранность при
сбое самого диска. Сломанный lock не удаляется автоматически: сначала проверить PID/
отсутствие писателя. База не предназначена для нескольких машин с сетевой FS.

Дедупликация — по SHA256 сохранённых представлений; устойчивый SRC ID относится к идентичности первоисточника. URL версии, дата и лицензия
сохраняются; одинаковый текст разных перепечаток не считается независимым подтверждением.
При разных URL с одинаковыми байтами сохраняется первый реестр — отдельные origins
при необходимости описать в журнале; мультипроисхождение не автоматизировано.

`revise` распространяет needs_review транзитивно по claims на решения и обещания.
`ingest --supersedes` делает то же для смены источника. Это явная команда, без фонового
мониторинга. После пересмотра ведущий агент выпускает новую рекомендацию и оставляет
старую с историей. CLI не оценивает истинность и не может доказать реальность ссылки
на человеческое подтверждение; ответственность за verified evidence остаётся у агента.

## Ограничения форматов

- UTF-8 MD/TXT/CSV; CSV ожидает запятую. Иная кодировка/разделитель требуют явной
  предварительной конвертации с сохранением происхождения.
- PDF с текстовым слоем; скан без OCR и encrypted PDF — ошибка/предупреждение,
  не «успешно прочитано». Сложная вёрстка требует сверки страницы.
- DOCX: параграфы и таблицы, без embedded objects, tracked changes/сносок как отдельной
  модели и без макросов. Ссылки на paragraph N и table N/row N.
- XLSX: значения/строки, лист и диапазон; формулы сохраняются как текст и не
  вычисляются. Не поддержаны macros, защищённые файлы, финансовый движок формул.
- HTML: статический текст, script/style не исполняются, JS/login не поддержаны.
  Это не браузерный scraping. Снимок отражает дату доступа; повторная загрузка
  с изменившимся хешем требует `--supersedes` при локальном импорте новой версии.
- Лимит 12 MB на источник/ответ; доверенные большие файлы предварительно разбить.
  DOCX/XLSX имеют лимит распаковки 64 MB/4096 entries; архивные бомбы не изолируются OS-контейнером: не импортировать неизвестные
  подозрительные бинарные файлы; использовать изолированную среду для них.

HTTPS fetch: точный allowlist домена, URL без userinfo, 20 секунд, лимит ответа,
проверка каждого redirect и глобальных DNS-адресов. В managed cloud локальный DNS
может отсутствовать: только фиксированные github.com/raw.githubusercontent.com
разрешается резолвить штатному `http://proxy:8080`, с запретом proxy bypass.
Произвольные домены без проверяемого DNS не разрешаются. Для прямой сети остаётся
TOCTOU DNS rebinding между проверкой и соединением; для враждебных доменов требуется
доверенный egress proxy с SSRF-защитой. Не считать этот клиент sandbox браузера.

## Перенос

Перенести весь архив, сохранив относительные пути; venv не копировать. Создать venv,
установить requirements.lock, установить пакет, выполнить doctor/tests/validate/resume.
Cursor-адаптер ссылается на AGENTS; в иной LLM-среде подключить тот же файл вручную.
Проверить доступность терминала, чтения файлов, сети, модели и стоимость. MCP, поиск,
смысловой поиск, OCR, аудио/видео, фоновый scheduler и автоматическая смена моделей
не появляются от переноса и здесь не реализованы. Приватные материалы переносить
только отдельно по разрешённому маршруту.


## Изменения контрактов 0.2.0

Стабильный ID относится к первоисточнику (identity_sha256); representations имеют
собственные sha256/path/extracted/extracted_sha256. Cache hit не отменяет замену;
циклы запрещены. Прямые и каскадные изменения повышают version. Стратегия зависит
от promise_ids; проверка и запись выполняются под одним lock. Решение содержит
формулировку выбора, вариант, decision_maker и owner; updates сохраняют ID/историю.

validate проверяет envelope/ревизии каждого исторического снимка и показывает
artifacts_restorable. Metadata не переписана; некоторые старые веб-байты после
минимизации недоступны — это предупреждение о восстановимости. Повреждение JSON —
ошибка. validation.py проверяет конфиг/workflow. Журнал разделяет результат/отказ,
фиксацию транзакции и реальные расходы; стоимость запроса не считается платежом.
