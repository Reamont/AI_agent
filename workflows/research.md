# Workflow от вопроса решения

| Этап | Выход и условие перехода | Если данные недоступны |
|---|---|---|
| A. Бриф | выбор, цель, метрика, получатель, ограничения и существенные трактовки | уточнить только развилку; сохранить допущения |
| B. План | вопрос → решение → гипотеза → метод/источник → затраты → достаточность | выбрать более дешёвую опровергающую проверку |
| C. Материалы | исходный хеш, дата, права, локатор, происхождение, группа независимости | ошибка и пробел, без сочинённого содержания |
| D. Анализ | факты/гипотезы/выводы/прогнозы/неизвестное, альтернативные причины | ограничить рекомендацию обратимым действием |
| E. Варианты | статус-кво, улучшение, другой сегмент/модель, закрытие | качественное сравнение вместо фиктивных баллов |
| F. Стратегии | продукт + коммуникация + обещания + проверка | не обещать ещё не доступную функцию |
| G. Поддержка | основания, владельцы, сроки, метрики, пересмотр, checkpoint | следующий шаг и неназначенные ответственные |

Вопросы в плане ранжируй по влиянию на выбор и стоимости опровержения. Не делай
обзор рынка ради количества источников. Перепечатки с общим исследованием — одна
группа независимости; задавай independence_group при описании анализа.

Стоп: достаточность для данного обратимого решения достигнута; исчерпан лимит;
стоимость неизвестна; нужен существенный выбор/новый доступ. Для дорогой необратимой
стратегии нужны более сильные основания. Тест понимания сообщения не доказывает спрос.

Для полного контракта полей стратегии см. `strategist/engine.py::strategy_errors`
и фактический `projects/demo/outputs/strategy.json`. Валидатор проверяет заполнение
и ссылки, но смысловую разницу вариантов и реалистичность оценивает ведущий агент.
